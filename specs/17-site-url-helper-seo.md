# 17 — site URL helper for SEO

**Status:** Implemented <!-- Draft | Approved — only a human may change this to Approved -->

## Goal

Add a shared `siteUrl()` utility backed by Astro's configured `site` and use it for same-origin page URLs generated by SEO metadata and JSON-LD. This removes duplicated domain configuration and manual page-URL concatenation while preserving the existing JSON-LD `@id` values.

## Scope

**In:**

- Add `src/utils/url.ts` with a `siteUrl(path)` helper that reads `import.meta.env.SITE` and builds absolute URLs with `new URL()`.
- Normalize page paths to a trailing slash, preserve query strings and fragments, and throw a build-time error when a page pathname contains uppercase letters.
- Preserve file-like paths such as `/llms/post.txt` without appending a slash. The LLM output adoption of the helper belongs to spec 18.
- Derive `COMPANY_INFO.url` from `siteUrl("/")` by removing only the final slash, so the company origin stays slashless and `astro.config.mjs` `site` is the only literal domain source.
- Make the sitemap filter in `astro.config.mjs` match route pathnames rather than repeating the production hostname. Preserve its current exclusions exactly.
- Use `siteUrl()` for same-origin page-valued fields emitted by `src/config/seo.ts` and `src/pages/servicios/index.astro`: canonical, `og:url`, breadcrumb `item`, and JSON-LD `url`/`serviceUrl` fields, including the services collection and its `hasPart` URLs.
- Preserve every current JSON-LD `@id` string exactly. Continue composing asset URLs separately from page URLs.
- Update `AGENTS.md`'s Config and Knobs map sections to document `astro.config.mjs` `site` as the domain source and `COMPANY_INFO.url` as a derived origin.

**Out:**

- Adopting the helper in the LLM text generators; covered by spec 18.
- Changing JSON-LD `@id` values or the graph structure.
- Passing logo/image assets, CDN URLs, social URLs, or client project URLs through `siteUrl()`.
- Rewriting visible relative `href` values or changing route files.
- Setting `trailingSlash: "always"` or changing Netlify redirects. Spec 04 deliberately chose explicit trailing-slash links instead of a build-wide routing change.
- Adding URL redirects, pages, a dependency, or new client-facing copy.

## Files affected

- New: `src/utils/url.ts` — exports `siteUrl()` backed by Astro's configured site.
- `src/config/companyInfo.ts` — derives `COMPANY_INFO.url` from `siteUrl("/")` without a trailing slash.
- `src/config/seo.ts` — routes page-valued SEO and JSON-LD URLs through `siteUrl()` while preserving `@id` values and asset/external URLs.
- `src/pages/servicios/index.astro` — routes the services collection and `hasPart` page URLs through `siteUrl()` while preserving their `@id` values.
- `astro.config.mjs` — removes repeated hostname literals from the sitemap filter without changing the configured `site` or the sitemap's URL set.
- `AGENTS.md` — updates the Config and Knobs map descriptions of the domain source.

These files are invariant SEO/configuration machinery under `AGENTS.md`'s “Invariant vs Variable” table. No row in “If you change X → update Y” covers a new `src/utils/` URL helper or a hostname-independent sitemap filter; the Config and Knobs map are updated in this spec to keep the contract accurate.

## Decisions made and discarded

The repo owner confirmed the scope and URL behavior on 2026-10-13.

- **Use Astro's configured `site` as the single domain source.** `COMPANY_INFO.url` derives from `siteUrl("/")` with only the final slash removed, so consumers that use it for stable identifiers do not change. Discarded: keeping separate literal domains in `astro.config.mjs` and `companyInfo.ts`, because they can drift.
- **Use `siteUrl()` for page URLs, not all URL-shaped strings.** Assets, external social URLs, and client project URLs keep their existing handling. Discarded: treating every string field as a page URL, because that would rewrite assets and external destinations.
- **Keep existing `@id` strings byte-for-byte.** They are stable identifiers referenced by the JSON-LD graph. Discarded: passing them through slash normalization, which would rename graph nodes and their references.
- **Normalize generated page URLs without changing routing.** Page paths get a trailing slash; file-like paths retain their filename form; uppercase page paths fail rather than being silently lowercased. Discarded: setting `trailingSlash: "always"`, which spec 04 rejected for this site.
- **Reuse the shared helper implementation from `/home/diferoca/scripts/hotfix-canonical-urls.md` § 2 Q11 and follow its URL contract in § 1 and § 3 steps 4–6.** Preserve Shine's stable `@id` values and the routing/link decisions already recorded in spec 04. Discarded: creating a Shine-specific URL-normalization policy.
